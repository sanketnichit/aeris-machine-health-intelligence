# Training-only operating-regime development protocol

The official FD001–FD004 labels are now observed. Do not tune against them. This experiment reads only the four complete training trajectory files, fingerprinted against the registered all-subset archive. Earlier FD001 development observations overlap this population; no independent validation claim.

Freeze one 60/20/20 engine-ID split per subset (seed 271), observable ages 50/100/150 cycles, fixed HGB candidates (150 iterations, seed 42), setting-space KMeans with known training regime counts (1/6/1/6), fixed scaling floors, and per-cluster sensor standardization fitted only on fitting engines. The features use current and past observations only. Compare the existing relative model, the regime-normalized model and an empirical age reference. Evaluate within-subset and FD001-to-other-subset development transfers. Neither official test trajectories nor RUL offset files are passed to the evaluation.

At each landmark, calibrate a 90% finite-sample quantile of the maximum observed setting distance along the prefix and an absolute-residual radius using one observation per surviving calibration engine. Insufficient survivors mean no finite threshold. A research forecast requires explicitly matching declared subset/domain, supported settings and a finite interval of width at most 80 cycles (a fixed illustrative policy, not an operational limit). Report ungated metrics, raw interval coverage, setting rejection, accepted counts, retained error and reasons. No conditional coverage guarantee after selection, no guarantee under shift, no fault-mode identification from settings. Repeated landmarks on the same engine are correlated. The domain metadata check is intentionally separate from the setting-distance score; matching settings cannot prove matching fault distributions.

No model selection on these results; use genuinely untouched evaluation data for later confirmation. No machine operation is authorized.
